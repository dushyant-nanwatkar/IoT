CHAPTER 1
ABSTRACT
AI and CV Powered Home Security System is a local doorway monitoring and communication
project built around an Android camera and audio endpoint, a high performance local computer,
and a homeowner web dashboard. It combines visitor observation, person detection, resident face
matching, dwell-based warnings, notices, and two-way audio within one local installation.
The Android client is assumed to send live video and microphone audio over Wi-Fi or an ADB
tunnel and to receive display text and audio feedback from the dashboard through the host. The
supplied backend uses FastAPI, WebSockets, PyAV, OpenCV, YOLO11, InsightFace, and
SQLite. Faster Whisper supports local voice-note transcription after model installation. Events,
snapshots, enrolled identities, and voice notes are stored locally.
The physical design includes an HD display, a high resolution high frame rate camera, IR
presence sensing, proximity measurement, controlled illumination, and a USB interface
controller. Sensor and lighting integration is proposed; the backend and dashboard are supplied,
while Android behavior follows the team’s stated client assumption.
The intended deployment is Level 1 style: one local authority performs analysis, stores data, and
hosts the application. The separate phone and computer require a composite-node qualification.
Optional Supabase upload and online Edge TTS must be disabled or replaced for strict offline
operation. Configured throughput and thresholds are design settings rather than measured results.

INTRODUCTION
A conventional doorbell announces arrival but provides little information about who is present or
whether a visitor remains near the entrance. A camera improves visibility, yet continuous manual
observation is impractical. This project combines local computer vision with interaction and
event storage to support homeowner review.
The phone supplies the doorway camera, microphone, display, and speaker. The host decodes
video, detects persons using YOLO11, compares face embeddings through InsightFace, applies a
dwell threshold, and delivers recent frames and alerts to the browser. OpenCV performs image
handling, overlays, and JPEG encoding. These roles distinguish person detection from identity
recognition.
Recognized residents can receive a display greeting. An unknown track that remains beyond the
configured threshold may produce a warning and snapshot. A homeowner can inspect the stream,
send a notice, or talk through the phone speaker. An unknown detection is a review cue and does
not prove intrusion.
Local processing reduces reliance on remote video analysis and keeps biometric records within
the premises. The Level 1 placement is examined separately in Chapter 7. Powerful GPU
hardware supports the workload but does not by itself determine an IoT deployment level.
The main objectives are live monitoring, enrolled-face comparison, reliable local records,
bidirectional feedback, and practical physical integration. The report distinguishes implemented
software, assumed Android behavior, proposed hardware additions, and tests still needed to
establish performance.

SCOPE
3.1 Functional Scope
1. Receive live camera and audio input from the assumed Android endpoint over local Wi-Fi or
ADB.
2. Detect persons, compare resident faces, track approximate dwell time, and generate event
records with available snapshots.
3. Provide enrollment, notices, camera commands, kiosk mirroring, telemetry, and two-way
audio through the dashboard.
4. Persist identities, events, voice notes, telemetry, and notices in SQLite with media files stored
locally.
5. Extend physical sensing with IR and distance inputs and a host-controlled lamp through a
proposed USB controller.
3.2 System Boundary
The supplied folder contains the Python host, static dashboard, communication specification, and
mock-phone utility. Android source is not supplied. Its capture, text display, and speaker
playback behavior is assumed as directed by the team. Sensor firmware, lamp wiring, and
backend sensor integration remain proposed.
The intended Level 1 style scope has one local decision and storage authority. Continuous video
archiving, cloud-dependent monitoring, validated anti-spoofing, and physical door unlocking are
outside the established implementation. No recognition accuracy, achieved frame rate, or
completed hardware validation is claimed.

REQUIREMENT ANALYSIS
4.1 Functional Requirements
1. Accept video/audio feeds and route text, commands, and playback audio to the phone.
2. Enroll residents, run person detection and face comparison, and show recent annotated frames.
3. Apply the configured three-second unknown dwell rule and store relevant events and media.
4. Provide notices, intercom, voice notes, telemetry, history, and connectivity status.
5. Integrate proposed IR, proximity, and lighting control with validated sensor messages.
4.2 Non-Functional Requirements
Keep frame age low through decoupled network and inference workers. Recover from
disconnected endpoints, bound queues and inputs, protect biometric data, restrict administrative
access, and maintain database/media backups. Browser microphone access on LAN may need
trusted HTTPS. Local hosting alone does not provide authentication.
4.3 Hardware Requirements
Provide an HD display, camera with suitable high resolution and frame rate, IR presence sensor,
short-range proximity sensor, diffuse low voltage light and driver, USB interface controller,
microphone, speaker, regulated supplies, mounting, and USB or local Wi-Fi connectivity. The
configured host target is Ryzen 7 250, 32 GB DDR5, and RTX 5060 with 8 GB VRAM. Actual
hardware capability requires verification.

5.2 Normalization and Connectivity
Single-column surrogate keys avoid partial dependencies. Third normal form depends on verified
business dependencies rather than the ORM alone. Embeddings and metadata are internally
structured JSON stored as text; a strict atomic-field interpretation needs qualification. Frequently
queried metadata should become typed columns.
SQLAlchemy async sessions use aiosqlite for local SQLite connectivity. Media paths refer to
local files, so backups must include both. Startup create_all creates missing tables; it is not a full
schema migration mechanism.

9.1 Communication and Processing
SBMP uses TCP port 9000 with a 9-byte big-endian header: channel byte, 32-bit timestamp, and 32-bit payload
length. Channels 0x01/0x02 carry video/audio; 0x03 carries mirror or notifications; 0x04 returns audio; 0x05
sends UI commands; 0x06 carries triggers and telemetry. ADB reverse forwards the phone TCP connection to
the host.
The host decodes frames into a buffer of capacity 20. The AI worker consumes recent frames at a configured
12 Hz, while the dashboard broadcast targets 30 Hz and may repeat annotations. Face cosine threshold is 0.48
and YOLO confidence is 0.45. These values need calibration and runtime verification.

person without a visible face in mixed scenes. Reprocessing the same latest frame is possible, so throughput
must include frame freshness.

CONCLUSION
The AI and CV Powered Home Security System combines local vision, visitor interaction, event
storage, and dashboard control. The supplied backend and web interface establish a practical
foundation; the Android endpoint is assumed to stream video/audio and receive text and speaker
feedback. IR and proximity sensing, lamp control, and physical wiring complete the proposed
hardware design once integrated and tested.
One local computer owns analysis, persistence, and application services. This supports a Level 1
style explanation when the installation is treated as one composite node, while the phone and host
remain separate physical devices. The design should therefore state its classification boundary
instead of treating locality alone as sufficient.
Fully local operation requires disabled cloud synchronization, installed model assets, local UI
resources, and offline speech. Recognition thresholds, frame rates, latency, and sensor behavior
require measurement on the actual installation. Future work should prioritize sensor firmware,
secure access, robust multi-person tracking, explicit migrations, retention, and repeatable
validation.
